# Goal 1 Plan

## 原始目标
基于现有项目进行继续开发，最终开发成一个功能成熟完善，性能（这里主要指视频的结构化转译、以及md即时渲染）优良的支持视频的知识库再完成功能。

## 当前项目理解
- 项目定位是视频优先的 AI 知识库，核心价值是把视频、音频、文档转化为可检索、可追溯、可编辑的 Markdown 知识资产。
- 技术栈以 Python 为主，GUI 使用 PyQt6，业务模块包括 `models/`、`utils/`、`backend/`、`frontend/`、`config.py`、`gui.py`。
- 当前可用测试入口包括 `python test_crucible_local.py`，仓库还存在 `test_core_features.py`。
- 必须优先保护用户数据、配置、API Key 和本地 vault，不自动上传素材到云端。

## 默认假设
- 目标是持续迭代式开发，不要求一轮完成全部成熟产品。
- 每轮只执行 `tasks.md` 中第一个未完成任务。
- 若发现已有实现与任务目标冲突，以当前 worktree 为准，先通过代码和测试确认再修改。
- 若需要新增依赖，优先使用现有依赖或 Python 标准库；确有必要时再评估。
- `goal-1/` 是计划文档目录，不纳入代码提交。

## 总体执行方案
1. 先建立当前系统基线：梳理模块、导入链路、测试状态、关键瓶颈和缺口。
2. 强化视频结构化转译流水线：来源元数据、hash、音视频探测、转写片段、关键帧、摘要、概念、事实核查、可追溯链接。
3. 强化 Markdown 知识资产生成：frontmatter、双链、来源页、片段页、主题页、反向链接、增量更新和备份。
4. 强化 Markdown 即时渲染性能：异步渲染、缓存、增量刷新、避免 GUI 阻塞。
5. 强化模型 Provider 配置与降级：OpenAI-compatible、DashScope、Ollama、LM Studio、本地 mock/离线兜底。
6. 强化数据一致性与索引：SQLite schema、路径路由、重复导入识别、可恢复失败状态。
7. 补齐离线测试和性能回归检查，避免依赖真实 API Key 或大文件。
8. 持续进行三任务一轮的大型检查-debug循环，及时修复偏离和隐患。

## 风险
- `gui.py` 体积较大，直接修改 UI 容易引入阻塞或回归。
- 视频处理和模型调用耗时，若未放入线程或任务队列会卡死 GUI。
- Markdown 渲染若全量刷新，会在大笔记或高频更新时明显卡顿。
- 用户数据位于 `data/`，测试和开发必须避免污染真实 vault。
- 现有 git 状态已有 `AGENTS.md` 修改，不能覆盖用户改动。
- Windows 环境下命令、路径和文件编码需要谨慎处理。

## 验证方式
- 每个任务至少执行针对性静态检查、单元测试或命令验证。
- 修改 Python 后优先运行相关测试，再运行 `python test_crucible_local.py`。
- 涉及核心功能时补充或更新离线测试。
- 涉及 GUI/渲染时尽量做可运行验证；无法自动验证时记录剩余风险。
- 检查 git diff，确保只包含本任务相关改动且未误带敏感数据。

## 回滚方案
- 每轮只改小范围文件，便于按文件回滚。
- 代码修改完成并验证后按规范提交，提交信息使用 Conventional Commits。
- 不使用 `git reset --hard`、`git checkout .` 等破坏性操作。
- 若某任务引入风险，优先用小补丁修复；必要时只回滚本轮提交涉及文件。

## 完成标准
- 视频导入到知识资产沉淀链路成熟：结构化元数据完整、内容可追溯、失败可恢复。
- Markdown 笔记即时渲染流畅，长文和增量更新下不明显阻塞 UI。
- Provider 配置灵活安全，本地/云端能力隔离清晰，云端不可用时有合理降级。
- 测试覆盖关键离线链路，构建和测试通过。
- 最终 review 从功能、性能、数据一致性、安全、权限、错误处理、文档、回滚角度无已知高风险问题。
